# apps/platform

Stack: **Next.js 16 (App Router, TypeScript, `src/` dir) + Prisma 7 + PostgreSQL + Tailwind CSS v4**. Session auth is a hand-rolled signed-cookie implementation (`jose` + `bcryptjs`), not a library — see [Auth](#auth) below for why.

This file only covers what's specific to this subproject. Product/architecture rationale lives in the root [../../CLAUDE.md](../../CLAUDE.md) and [../../docs/](../../docs/).

## Important: this Next.js version is newer than typical training data

This was scaffolded with `create-next-app@latest` in July 2026 → Next.js 16.2.12, React 19.2.4. The framework itself ships a warning (`AGENTS.md` in this directory, `node_modules/next/dist/docs/`) that APIs and conventions may differ from what an LLM expects. Concretely, versus older Next.js knowledge:

- **`middleware.ts` is now `proxy.ts`** (`export default async function proxy(req)`, same `config.matcher` shape). This project uses `proxy.ts` for optimistic auth redirects — don't reintroduce `middleware.ts`.
- `params` and `searchParams` on pages are `Promise`s — always `await` them.
- Global `PageProps<'/route'>` / `LayoutProps<'/route'>` / `RouteContext<'/route'>` helper types exist (generated by `next dev`/`next build`/`next typegen`) — prefer them over hand-writing prop types.
- Before using a Next.js API you're not sure about, check `node_modules/next/dist/docs/` in this directory rather than relying on training data.

## Auth

No auth library (NextAuth/Auth.js, etc.) — a small hand-rolled implementation instead, following the pattern Next.js's own docs recommend for a DIY approach:

- `bcryptjs` for password hashing (pure JS — avoids native-binding install issues; swap for `bcrypt` later if perf matters).
- `jose` to sign/verify a session JWT stored in an `httpOnly` cookie (`src/lib/session.ts`).
- `src/lib/dal.ts` centralizes `verifySession()` (memoized with React `cache()`) — call it from Server Components/Actions/Route Handlers close to the data, per [docs/architecture.md](../../docs/architecture.md#tenancy--users)'s "internal auth placeholder" item.
- `proxy.ts` does the optimistic redirect (no session → `/login`); `verifySession()` in the DAL is the real enforcement point, not the proxy.

This is deliberately the credentials-only "internal user" placeholder from [docs/todo.md](../../docs/todo.md) Phase 1 — it's not what Okta federation looks like in Phase 3, but the DAL boundary is where an OIDC/SAML session gets swapped in later without touching call sites.

## Data

`prisma/schema.prisma` implements the entities in [docs/data-model.md](../../docs/data-model.md), including the `rejected`/`cancelled` `PurchaseOrder` states. Local Postgres via `docker-compose.yml` at the repo root's `apps/platform` — not SQLite, because the schema relies on native Prisma enums, which SQLite doesn't support.

## Local dev

```bash
docker compose up -d        # Postgres on localhost:5434 (5432 and 5433 were already taken by other local Postgres instances)
npm install
npx prisma migrate dev      # create schema
npm run seed                 # demo tenant + internal user + one open action item
npm run dev                  # http://localhost:3000
```

Seeded login is printed by `npm run seed`.
